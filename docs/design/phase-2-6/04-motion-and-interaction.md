# Motion, interaction and illumination

Motion explains state changes; it never drives saving, validation or scheduling. CSS transitions are the default; no Motion/Rive dependency is proposed. [Research rationale](01-design-vision.md) distinguishes library capabilities from a need to install them. The usable interface must work with every duration set to zero.

## Shared interaction-lighting contract

The V6 **Play light cue** button demonstrates technique; it is **not a production control**. Navigation, primary actions and real planner controls request lighting on actual accepted native activation, equally for pointer, keyboard and touch. Disabled controls do not activate. Keep the original functional handler independent and execute it once; no animation promise gates an update, scrolling or focus.

| Stage                    | Required meaning and visual response                                                                                                                                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Activation               | Immediate pressed/current/focus state plus restrained **local** reflected edge/light response; navigation/primary/planner actions share one visual policy, not unrelated per-button timelines. It means “activated”, never “saved”, “locked” or “scheduled”. |
| Operation success        | Only the actual successful operation/adoption/persistence result permits confirmation words/icons and optional 120ms local emphasis. Existing academic and scheduling save semantics remain distinct.                                                        |
| Operation failure/cancel | Persistent real warning/conflict/draft behavior, no success state; cancel/replace activation decoration without clearing data. An already-fired activation cue is not evidence of successful persistence.                                                    |

Default local response ~180ms, standard easing; fine reflections may coordinate with the shared environment light field. Explicit appearance selection may use a bounded environmental response; no full-page pulse for every keystroke or routine button. Reference cue budget is **≤1,180ms** including any offsets, not a mandatory duration for all buttons. Repeat activation cancels/replaces the previous decoration (no queues, timers per layer or growing listeners). Reduced motion/effects/forced colors provide immediate static pressed/current feedback and real result labels without lighting animation.

Decorative layers are pointer-transparent, inert/aria-hidden and separate from text/focus/backplates. Hidden/offscreen/pause, reduction, renderer disposal and appearance changes cancel nonessential cues before the next paint; restoration never replays them. Touch uses restrained activation/press rather than hover dependence. No blur/layout/keyboard/viewport animation or text glow. The 112×8 capsule receives the existing ambient field only: **no extra cue target or loop**.

Lattice and Landscape share coordinated environmental movement (CSS/SVG), with moonlight colors in Dark; Basic intentionally omits ongoing background motion but retains immediate control feedback. Reduced motion freezes nonessential continuous movement, not merely slowing it; reduced effects makes chrome/content opaque and removes decorative atmosphere. No perpetual bright flashing or star twinkle. Motion must remain interruptible and gracefully static if the browser cannot animate the shared field.

## Accessibility and cancellation rules

Effective reduced motion = OS `prefers-reduced-motion: reduce` OR the user's Reduce motion preference OR effective reduced effects/forced colors. Effective reduced visual effects = OS `prefers-reduced-transparency: reduce` OR the user's Reduce visual effects preference; forced colors also implies solid surfaces. A user preference may add reduction but cannot force motion against an OS reduction. Toggling a reduction cancels current nonessential effects immediately, preserving focus and values.

Use `focus-visible` outlines, including keyboard navigation on menus. Native button/checkbox/radio semantics carry state, not animated icons alone. Do not announce every render or every pointer hover. Save failure and blocking conflict use persistent visible text and an appropriately scoped alert; routine success may use polite status. Avoid live announcements repeating all conflict rows each time the form rerenders.

## Performance and dependency gate

Animate opacity/color and small transforms only; no layout-driven animation of week grids, blur kernels, viewport height, safe-area padding or native fields. Keep at most one translucent navigation layer visible; menus replace rather than stack glass. Profile scrolling and typing on a physical lower-powered iPhone/iPad with effects on/off. Effects that introduce repeated frame stalls or field lag are removed before launch. This is an acceptance test, not a claim that a static spec guarantees a frame rate.

Motion for React would need a separately justified orchestration case that CSS cannot express clearly, bundle/runtime measurement, interruption tests and reduced-motion parity. Rive would require an actual product need for a nonessential illustration and semantic fallback. Neither is justified by the current planner. View Transition API is researched as optional future enhancement, not a dependency or requirement for this redesign. Unsupported browsers show the new state immediately.

Successful assignment saving would use the same post-success rule, but academic failed saves have different existing in-memory semantics: retain the record and persistent warning, never claim persisted success. Do not copy schedule rollback into academic capture as part of motion work.

For each study, changing reduced-motion preferences cancels nonessential transitions immediately, preserving semantic state and focus. Changing reduced-effects removes reflection/blur/halo, independently of motion. Failure messages are solid and still. Historical static Night specimens are not the final atmosphere: Lattice/Landscape now use the approved coordinated movement; Basic remains static. Activation uses the shared lighting contract below, never width, native-field geometry or blur animation. Touch feedback does not shrink hit targets. The showcase is not a measured performance result or a full application interaction test.
